# Σύγκριση Τιμών Σούπερ Μάρκετ — Design Spec

**Ημερομηνία:** 2026-06-26
**Κατάσταση:** Εγκεκριμένο design, έτοιμο για implementation plan
**Stack:** Pure PHP 8.x + MySQL/MariaDB, σε VPS

---

## 1. Σκοπός

Δημόσιο site σύγκρισης τιμών σούπερ μάρκετ (στο πνεύμα του bigle.gr / posokanei.gov.gr).
Ο χρήστης ψάχνει ένα προϊόν (π.χ. «γάλα ΝΟΥΝΟΥ 1λ») και βλέπει την τιμή του σε
πολλές αλυσίδες, ταξινομημένη φθηνότερο→ακριβότερο, με κουμπί που τον στέλνει στο
επίσημο e-shop. Επιπλέον ένα κουμπί «Βρες μου τιμές για τα βασικά» που συγκρίνει το
**συνολικό κόστος ενός καλαθιού βασικών** ανά αλυσίδα.

### Scope MVP
- **3 αλυσίδες:** Σκλαβενίτης, ΑΒ Βασιλόπουλος, Μασούτης (οι μεγαλύτερες πανελλήνια,
  επιβεβαιωμένο ότι έχουν δουλεύσιμα product sitemaps).
- **Επιλεγμένος κατάλογος ~500–2.000 δημοφιλή προϊόντα** (όχι ο πλήρης κατάλογος των
  50.000). Τα «βασικά» είναι ο πυρήνας του καταλόγου.

### Εκτός scope (MVP)
- Υπόλοιπες αλυσίδες (My market, Κρητικός, Γαλαξίας, Χαλκιαδάκης κ.λπ.) — προστίθενται μετά.
- Πλήρης κατάλογος προϊόντων.
- Λογαριασμοί χρηστών / αγαπημένα / barcode scanner από κινητό (μελλοντικά).

## 2. Κρίσιμες διαπιστώσεις (από live έρευνα)

Επιβεβαιώθηκαν ζωντανά στις πραγματικές σελίδες και διαμορφώνουν την αρχιτεκτονική:

1. **Δεν υπάρχουν δημόσια XML feeds τιμών.** Τα supermarket βγάζουν XML μόνο για
   Skroutz/BestPrice (marketplaces), όχι ανοιχτό feed για τα δικά τους e-shops.
   Μοναδική πηγή = ανάγνωση των σελίδων τους.

2. **Τα e-shops ΔΕΝ δείχνουν EAN/barcode** στη σελίδα προϊόντος — μόνο δικούς τους
   εσωτερικούς κωδικούς (Σκλαβενίτης: `1478687`, ΑΒ: `7617631`). Άρα **αυτόματο
   ταίριασμα μεταξύ αλυσίδων με βάση το EAN δεν είναι εφικτό.** Το EAN είναι κλειδί
   που **εμείς** εισάγουμε (το ξέρουμε/το σκανάρουμε), όχι κάτι που τραβάμε από τα stores.

3. **Κάθε αλυσίδα θέλει διαφορετική μέθοδο εξαγωγής τιμής:**
   - Σκλαβενίτης → η τιμή υπάρχει σε καθαρό server-side HTML (parse HTML).
   - ΑΒ → SPA, η τιμή φορτώνει με JavaScript → κλήση του εσωτερικού JSON API τους.
   - Μασούτης → προς επιβεβαίωση στο implementation (πιθανόν HTML).
   Δεν υπάρχει «ένας scraper για όλους» — bespoke parser ανά αλυσίδα.

4. **Νομικό πλαίσιο:** οι Όροι Χρήσης των e-shops απαγορεύουν τη μαζική «συλλογή και
   χρήση περιεχομένου»· η βάση τιμών προστατεύεται από sui generis database right.
   Άρα η σχεδίαση είναι σκόπιμα **αμυντική** (βλ. §8).

## 3. Αρχιτεκτονική — 4 ανεξάρτητες μονάδες

```
1. PUBLIC SITE (PHP)        2. ADMIN PANEL (PHP, login)
   - Αναζήτηση                  - Προσθήκη προϊόντος (EAN)
   - Σελίδα σύγκρισης           - Ημι-αυτόματη αντιστοίχιση URLs/3 αλυσίδες
   - Κουμπί «Βασικά»            - Επισκόπηση / διόρθωση
   - Κουμπιά link-out
        │                            │
        └──────────► 3. MySQL ◄──────┘
                        ▲
        ┌───────────────┘
        │
   4. SCRAPER (PHP CLI + cron, 1×/μέρα)
        - Σκλαβενίτης: HTML parse
        - ΑΒ: JSON API
        - Μασούτης: TBD
        - refresh ΜΟΝΟ των αποθηκευμένων URLs
        └──► τα 3 e-shops

   Open Food Facts ──► (μία φορά ανά EAN: όνομα + φωτό), τραβιέται από το Admin.
```

**Αρχή απόζευξης:** Public site και Scraper είναι τελείως αποσυνδεδεμένα. Το public
site διαβάζει **μόνο** από τη βάση, ποτέ δεν κάνει live scraping. Αν σπάσει ένας
scraper, το site συνεχίζει να δείχνει τις τελευταίες γνωστές τιμές με ένδειξη
«ενημερώθηκε πριν X». Καμία αλυσίδα που χαλάει δεν ρίχνει όλο το site.

### Μοντέλο δεδομένων: «map-once, refresh-daily»
- **Αντιστοίχιση (μία φορά ανά προϊόν, ημι-αυτόματα μέσω Admin):** βάζεις EAN → OFF
  δίνει όνομα+φωτό → το σύστημα ψάχνει τα e-shops και προτείνει υποψήφια URLs → εσύ
  επιβεβαιώνεις. Αποθηκεύεται `EAN → { URL Σκλαβενίτη, URL ΑΒ, URL Μασούτη }`.
- **Ανανέωση τιμών (καθημερινά, αυτόματα μέσω cron):** ξαναδιαβάζει **μόνο** τα γνωστά
  URLs, ενημερώνει **μόνο** την τιμή. Δεν ψάχνει, δεν ταιριάζει.

Το δύσκολο (matching, με ανθρώπινο έλεγχο) απομονώνεται σε one-time βήμα· το καθημερινό
γίνεται τετριμμένο και αξιόπιστο.

## 4. Σχήμα βάσης δεδομένων

```
stores
  id · name · slug · logo_url · active

products            -- ο κατάλογος· EAN = το κλειδί που εισάγουμε εμείς
  id
  ean               UNIQUE
  name              -- από Open Food Facts
  brand
  image_url         -- από Open Food Facts (ή fallback generic)
  category          -- «Γαλακτοκομικά», «Όσπρια»...
  is_basic          -- 0/1 → μπαίνει στο κουμπί «Βασικά»
  created_at / updated_at

product_links       -- η αντιστοίχιση (μία γραμμή ανά προϊόν×κατάστημα)
  id
  product_id        FK → products
  store_id          FK → stores
  product_url       -- το αποθηκευμένο link που κάνει refresh ο cron
  store_internal_code
  current_price
  price_per_unit    -- €/κιλό ή €/λίτρο (για σωστή σύγκριση)
  last_scraped_at
  scrape_status     -- ok | failed | out_of_stock
  UNIQUE(product_id, store_id)

price_history       -- 1 γραμμή/μέρα/link → γραφήματα τάσης τιμής
  id · product_link_id FK · price · recorded_on

admin_users
  id · username · password_hash
```

**Σημεία-κλειδιά:**
- `price_per_unit` → σωστή σύγκριση ανεξάρτητα μεγέθους συσκευασίας (€/λίτρο, €/κιλό).
- `price_history` → differentiator: γράφημα «πώς πήγε η τιμή τον τελευταίο μήνα».
- `is_basic` → ξεκλειδώνει το «σύνολο καλαθιού ανά αλυσίδα».

## 5. Πηγή ταυτότητας προϊόντος: Open Food Facts

- Ανοιχτή βάση (ODbL) με όνομα + μάρκα + φωτό ανά EAN — νόμιμα ελεύθερη χρήση.
- Τραβιέται **μία φορά**, τη στιγμή που προσθέτεις το προϊόν στο Admin.
- **Fallback:** η ελληνική κάλυψη του OFF είναι μικρότερη της γαλλικής — όταν λείπει
  προϊόν, ο admin βάζει χειροκίνητα όνομα + generic/δική του φωτό.

## 6. Εμπειρία χρήστη

**Αρχική:** μεγάλο search (autocomplete) + κουμπί «🧺 ΒΡΕΣ ΜΟΥ ΤΙΜΕΣ ΓΙΑ ΤΑ ΒΑΣΙΚΑ»
+ κατηγορίες.

**Σελίδα προϊόντος (καρδιά):**
- Φωτό + όνομα + EAN.
- Πίνακας αλυσίδων **ταξινομημένος φθηνότερο→ακριβότερο**: τιμή, €/μονάδα,
  «⏱ ενημερώθηκε πριν X», κουμπί «Δες το →» (link-out στο επίσημο e-shop).
- Επισήμανση φθηνότερου + πόσο γλιτώνεις.
- Μίνι γράφημα ιστορικού τιμής 30 ημερών.
- Αν λείπει τιμή από αλυσίδα → «μη διαθέσιμο» (δεν κρύβεται η αλυσίδα).

**Σελίδα «Βασικά» (killer feature):**
- Banner: **συνολικό κόστος καλαθιού ανά αλυσίδα**, π.χ.
  «Μασούτης 43,80€ ✅ · Σκλαβενίτης 45,20€ · ΑΒ 46,10€».
- Λίστα κάθε βασικού προϊόντος με το φθηνότερο κατάστημα δίπλα.
- Απαντά στην πραγματική ερώτηση: «πού να κάνω **όλα** τα ψώνια φθηνότερα».

## 7. Scraping — λειτουργία, λάθη, hosting

**Cadence:** 1×/μέρα ~04:00 μέσω cron. Σειριακά & αργά (1–2″ ανά request, ρεαλιστικό
User-Agent). ~3.000 σελίδες × 1,5″ ≈ 75′. Refresh **μόνο** γνωστών URLs (όχι discovery).

**Διαχείριση λαθών:**
- Κάθε scrape σε `try/catch`· σε αποτυχία **κρατά την τελευταία καλή τιμή** +
  `scrape_status=failed`. Ποτέ δεν σβήνει σωστά δεδομένα.
- Αν ολόκληρη αλυσίδα αποτύχει >50% (= άλλαξαν το site) → **email ειδοποίηση** στον admin.
- Ανίχνευση εξάντλησης/404 → «μη διαθέσιμο», ποτέ λάθος τιμή.

**Hosting:** φθηνό VPS (~5€/μήνα) — cron + εξερχόμενα HTTP + PHP CLI χωρίς timeout.
PHP 8.x, MariaDB/MySQL, PDO, χωρίς βαρύ framework.

## 8. Νομική υγιεινή (σκόπιμα αμυντική σχεδίαση)

- **Link-out πάντα** — στέλνουμε κίνηση στα e-shops, δεν κρατάμε χρήστη.
- Από τα stores παίρνουμε **μόνο την τιμή** (γεγονός). Φωτό/όνομα από Open Food Facts.
- «⏱ ενημερώθηκε πριν X» σε κάθε τιμή.
- Αργό/ευγενικό crawl, εκτός ωρών αιχμής.
- Σελίδα Όρων: «οι τιμές είναι ενδεικτικές — δες την επίσημη στο κατάστημα».
- Διαβάθμιση ρίσκου που αποφεύγουμε: τιμή (ελαφρύ) < +όνομα < +φωτό/περιγραφή
  αντιγραμμένη (βαρύ). Γι' αυτό η φωτό/περιγραφή ΔΕΝ έρχεται από τα stores.

---

## 9. Testing

- **Golden fixtures:** 1 αποθηκευμένο δείγμα σελίδας/JSON ανά αλυσίδα· test ελέγχει
  ότι ο parser βγάζει σωστή τιμή + €/μονάδα. Όταν αλλάξει το site, το test **σπάει
  δυνατά** αντί να μπαίνουν σιωπηλά σκουπίδια.
- **Dry-run mode** στον scraper (τρέχει χωρίς εγγραφή στη βάση).
- Unit tests στη λογική σύγκρισης (ταξινόμηση, €/μονάδα, σύνολο καλαθιού).

## 10. Ανοιχτά σημεία για το implementation plan

1. Επιβεβαίωση μεθόδου εξαγωγής τιμής για **Μασούτη** (HTML vs JSON API).
2. Εντοπισμός του εσωτερικού **JSON API endpoint του ΑΒ** (SAP Hybris) για τιμή/απόθεμα.
3. Anti-bot ανθεκτικότητα (Cloudflare/throttling) — στρατηγική retry/backoff.
4. Αρχικό seed list «βασικών» προϊόντων (~20–30 για πρώτη σελίδα Βασικών).
5. Μηχανισμός autocomplete αναζήτησης (MySQL FULLTEXT vs LIKE).
